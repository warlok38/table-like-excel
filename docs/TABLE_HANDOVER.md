# Таблица с поведением как в Excel

## Что это

Самостоятельный компонент для просмотра и редактирования табличных данных. Поддерживает объединённые ячейки, выделение диапазонов, изменение значений, фона и примечаний.

Демонстрационная страница: `/features/custom-table`. Для локального просмотра запустить `npm.cmd run dev` из корня проекта и открыть этот путь.

Для первого знакомства: выделить несколько ячеек, выбрать цвет и нажать «Отмена». Затем изменить доступное значение, добавить примечание, если оно требуется, и нажать «Сохранить». Так можно увидеть разницу между локальными правками и сохранёнными данными.

## Как пользоваться

- Клик выделяет ячейку, протягивание мышью — диапазон. `Ctrl + клик` добавляет или убирает отдельную ячейку, `Ctrl + протягивание` добавляет диапазон к выделению.
- Стрелки перемещают выделение, `Shift + стрелки` расширяют его. `Tab` и `Shift + Tab` переходят между ячейками.
- Двойной клик или `Enter` открывает редактор. Для текстовых и числовых ячеек можно сразу начать печатать, заменяя прежнее значение. `Delete` очищает значения выделенных ячеек, если их разрешено редактировать.
- Цвет из палитры применяется к выделенным ячейкам, для которых разрешена смена фона. Палитра приходит вместе с данными, поэтому набор цветов можно менять без правки интерфейса.
- Правый клик открывает действия с примечанием: добавить, изменить или удалить. Ячейка с примечанием отмечена небольшим маркером.

Редактор зависит от настроек ячейки: текст, многострочный текст, число, список или дата. Разрешения на изменение значения, фона и примечания задаются отдельно в данных ячейки.

## Как работают изменения

Правки сначала остаются локально и видны в таблице. **«Сохранить»** отправляет только изменённые значения, цвета и примечания. Во время запроса редактирование блокируется. Успешный ответ становится новой сохранённой версией; при ошибке правки остаются для повторной попытки.

**«Отмена»** возвращает таблицу к последней успешно сохранённой версии без запроса к API.

Для некоторых ячеек изменение значения требует нового непустого примечания. Ранее загруженное примечание не заменяет объяснение новой правки; без него сохранение не проходит. У таких ячеек удаление примечания запрещено.

Большие таблицы, начиная со 100 строк, показывают преимущественно строки в видимой области. Это уменьшает нагрузку на браузер. При выделении мышью у края таблица автоматически прокручивается.

## Где продолжать работу

- `src/components/Table` — сам компонент. `useTableController` управляет состоянием, `TableSurface` показывает таблицу, `TableHeaderActions` — палитру и кнопки. Логика выделения, редактирования, примечаний и сохранения разделена внутри `model`.
- `src/integrations/table` — загрузка, сохранение и связь ячеек с идентификаторами backend. Здесь подключается реальный API.
- `src/mocks/table` — демонстрационные данные и имитация сохранения.

Компонент не зависит от Next.js, Redux или моков. Он получает данные, палитру, флаг управления ячейками и функцию сохранения. Эта функция должна вернуть подтверждённую таблицу. Ключи ячеек должны оставаться уникальными и стабильными.

`DataStatus` — дополнительные сведения о ячейке: фон, примечание и требование объяснять изменение значения. В демо наличие `DataStatus` включает выделение, навигацию и действия с фоном и примечаниями. Редактирование значения определяется настройками самой ячейки.

## Текущее состояние

Демо работает на моках в памяти: после перезагрузки страницы изменения исчезают. Реальный backend ещё нужно подключить. Внешние обновления не подменяют таблицу во время локальных правок; объединение конфликтующих изменений не реализовано.
