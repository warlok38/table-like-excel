# Страница правил параметров

## Что это

Страница для настройки параметров журнала: значения по умолчанию, условий оформления и текстов уведомлений. Параметр выбирается из готового справочника; новые параметры на этой странице не создаются.

Правило связывает **условие** с **результатом**. Например: «значение больше 100 → красный цвет и текст уведомления». Значение по умолчанию — отдельная числовая настройка без условия сравнения. Можно сохранить только его, только обычные правила или оба варианта.

Страница сохраняет настройки. Применение правил к рабочим данным и отправка уведомлений здесь не выполняются; с Excel-подобной таблицей фича пока не связана.

Демонстрационная страница: `/features/antd-table`. Для локального просмотра запустить `npm.cmd run dev` из корня проекта и открыть этот путь.

## Основной сценарий

1. **Найти параметр.** В таблице показаны параметры с сохранёнными настройками. Лупа в колонке «Название» открывает поиск: ввести часть названия, нажать «Найти» или `Enter`. «Сбросить» убирает фильтр. Карандаш открывает редактор.
2. **Настроить новый параметр.** Нажать «Настроить параметр» и выбрать запись из справочника. Поиск учитывает название, ID, тип плана, агрегацию и смену. При выборе смотреть и на эти характеристики: они определяют контекст новых правил. Если настройки уже есть, откроется их редактирование.
3. **Заполнить форму и сохранить.** Задать значение по умолчанию и/или добавить правила. Для правила нужны название, знак сравнения, числовой порог и хотя бы один результат: стиль или уведомление. Описание необязательно. После успешного сохранения форма закрывается, таблица обновляется.

Счётчик «Правила» в таблице учитывает только обычные условия. Поэтому параметр только со значением по умолчанию отображается с нулём правил.

## Что можно менять в форме

- **Значение по умолчанию:** задать, изменить или очистить. Ноль считается заданным значением.
- **Правила:** раскрыть карточку, изменить название, описание, стили и тексты уведомлений. У сохранённого правила знак сравнения и порог заблокированы; для другого условия нужно удалить правило и создать новое.
- **Результаты:** выбрать свойство оформления из справочника и ввести его значение либо добавить текст уведомления. Одно правило может содержать несколько стилей и уведомлений.
- **Поиск:** найти карточку по названию правила или характеристикам агрегации. Новые правила помечены «Новое», изменённые существующие — «Изменено». После успешного сохранения метки исчезают.

Тип плана, уровень и способ агрегации берутся из выбранной записи справочника, а не вводятся вручную. Например, «Факт / Сутки / Среднее» описывает, к каким данным относится настройка. Если этих сведений нет, создание обычного правила или нового значения по умолчанию блокируется с объяснением в форме. Изменять и удалять уже сохранённое значение по умолчанию можно без них.

## Удаление и отмена

Удаление отдельной карточки, стиля или уведомления сначала меняет только **черновик** — несохранённую версию формы. Существующие элементы можно восстановить через «Ожидают удаления». На сервер удаление отправится после «Сохранить».

**«Удалить все правила» действует сразу после подтверждения:** удаляет все обычные правила, их оформление и уведомления **и значение по умолчанию**. Кнопка есть и у параметра только со значением по умолчанию. После полной очистки параметр исчезает из таблицы настроенных, но остаётся в справочнике для повторной настройки.

«Отмена», закрытие формы и «Назад» предлагают подтвердить потерю несохранённых правок. Уже выполненные запросы сохранения этим не отменяются.

## Как работает сохранение и что происходит при ошибке

Перед записью проверяются обязательные поля, заполненность результатов и повторяющиеся условия в одном контексте. Новую пустую настройку сохранить нельзя; полностью удалить существующую можно. При ошибке проверки форма показывает проблемное поле и раскрывает карточку правила, если ошибка в нём.

Отправляются только отличия от загруженной версии: сначала удаления, затем изменения, затем один общий запрос создания новых записей. После записи перечитываются два набора данных: справочники и настройки параметров.

- **Ошибка записи:** очередь останавливается. Часть изменений уже могла сохраниться; оставшиеся правки остаются в форме для исправления и повторного сохранения.
- **Ошибка обновления данных:** запись блокируется. «Повторить загрузку» только перечитывает данные, не отправляя изменения повторно.
- **Потерян ответ на создание:** повторная запись блокируется, чтобы избежать дублей. Нужно закрыть форму, проверить сохранённые настройки и только затем продолжать.

## Где продолжать работу

Фича находится в `src/widgets/parameter-rules`:

- `ui/ParameterRulesWidget.tsx` соединяет страницу, выбор параметра и редактор. В `ui` находятся все экранные компоненты.
- `model/useParameterRulesController.ts` управляет загрузкой и открытием форм; `useParameterEditorController.ts` — черновиком и проверками. `saveOperations.ts` готовит запросы, `useRulesSaveSession.ts` выполняет очередь и обрабатывает сбои.
- `api/parameterRulesApi.ts` содержит RTK Query; `contracts.ts` — форматы запросов и ответов, `parameterRulesAdapter.ts` — преобразование ответов для интерфейса. Здесь подключается реальный API.

## Текущее состояние

Запросы пока вызывают локальный сервис из `api/mock`. Данные хранятся в памяти и сбрасываются после перезагрузки страницы; журнал и автор тоже демонстрационные.

Шкалы, каналы и получатели уведомлений в форме не настраиваются. Перед подключением backend нужно сверить контракты и ключи свойств оформления.

Подробности API и готовые сценарии ошибок: [README фичи](../src/widgets/parameter-rules/README.md).
