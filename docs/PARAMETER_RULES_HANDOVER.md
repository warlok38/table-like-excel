# Страница правил параметров

## Что это

Страница для настройки правил конкретного параметра в журнале: значения по умолчанию, условий оформления и текстов уведомлений.

Например, можно задать условие «значение больше 100» и связать с ним цвет или уведомление. Страница создаёт и сохраняет эти настройки; применение правил к рабочим данным и отправка уведомлений здесь не выполняются.

Демонстрационная страница: `/features/antd-table`.

## Как пользоваться

В таблице показаны параметры, для которых есть настройки: ID, название, описание и количество обычных правил. Значение по умолчанию в этот счётчик не входит.

**«Настроить параметр»** открывает выбор из справочника. Можно найти параметр по названию, ID или связанным характеристикам. Кнопка с карандашом открывает настройки уже добавленного параметра.

В форме доступны:

- **Значение по умолчанию.** Можно задать число, изменить или очистить его. Ноль считается заданным значением. Допускаются настройки только с этим значением, только с условиями или с обоими вариантами.
- **Правила.** У каждого есть название, необязательное описание, знак сравнения, числовой порог и результат: стили, уведомления или оба варианта. Знаки и свойства оформления берутся из справочников. Есть поиск по названию и агрегации.
- **Удаление.** Отдельные правила, стили и уведомления удаляются сначала из черновика. До сохранения существующие элементы можно восстановить в блоке «Ожидают удаления».

У существующего правила знак сравнения и порог заблокированы: чтобы изменить условие, нужно удалить правило и создать новое. Название, описание и результаты редактируются.

Кнопка **«Удалить все условия»** после подтверждения сразу запускает сохранение удаления обычных правил вместе с их стилями и уведомлениями. Ранее сохранённое значение по умолчанию остаётся.

## Как работает сохранение

Форма хранит отдельный черновик. Перед сохранением проверяются обязательные поля, заполненность результатов и дубли условий. Новую пустую настройку сохранить нельзя. При закрытии формы с правками появляется предупреждение об их потере.

Сохранение выполняется последовательно: удаления → изменения → создание. Новые записи отправляются одним общим запросом. После этого перечитываются справочники и настройки; при полном успехе форма закрывается.

Вся очередь не является одной транзакцией: при ошибке часть изменений уже может сохраниться. Форма сообщает об этом и сохраняет оставшиеся правки. Если обновить данные не удалось, запись блокируется до успешной повторной загрузки. Если ответ на создание потерян, повторное создание блокируется: нужно закрыть форму и проверить, что уже сохранилось.

## Где продолжать работу

Вся фича находится в `src/widgets/parameter-rules`:

- `ui` — таблица, выбор параметра и форма редактора; входной компонент — `ParameterRulesWidget`.
- `model` — черновик, проверки, контроллеры страницы и редактора, подготовка очереди и обработка сохранения.
- `api` — контракты, преобразование ответов и RTK Query. Сейчас запросы вызывают сервис из `api/mock`; здесь подключается реальный API.

## Текущее состояние

Данные хранятся в памяти мок-сервиса и сбрасываются после перезагрузки. Контекст журнала и автор тоже демонстрационные. Эта страница и Excel-подобная таблица пока работают отдельно.

Шкалы, каналы и получатели уведомлений в форме не настраиваются. Перед подключением backend нужно сверить контракты и ключи свойств оформления.

Подробности API и готовые сценарии ошибок: [README фичи](../src/widgets/parameter-rules/README.md).
